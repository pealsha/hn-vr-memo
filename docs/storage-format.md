# 保存形式 v2 と復旧

各ページは同じベース名の `yyyyMMdd-HHmmssfff-<guid>.json` と `.png` で保存する。新規ページの日時部分は、ページ作成時刻 (UTC) をその PC のローカル時刻へ換算した値である。GUID は同時作成でも名前が衝突しないための識別子で、同じページを保存し直しても名前は変わらない。アプリを開いている間に PC のタイムゾーンが変わっても、すでに保存したページのベース名は変えない。既存の UTC 名ファイルも改名せず、その名前のまま更新する。

JSONが正本（編集に必要な元データ）、PNGは派生画像。書込はv2、読込はv1・v2に対応する。色・太さと消しゴム、PC・VRのページ一覧に対応する。

## v2 の JSON

UTF-8で保存する。以下は有効な形式の例。

```json
{
  "formatVersion": 2,
  "id": "2f00f4d6-961b-4282-852f-f1c86b1a155c",
  "createdUtc": "2026-09-27T10:00:00+00:00",
  "updatedUtc": "2026-09-27T10:00:04+00:00",
  "boardWidthMetres": 0.48,
  "boardHeightMetres": 0.36,
  "isPinned": false,
  "title": "謎解きのメモ",
  "strokes": [{
    "startedUtc": "2026-09-27T10:00:01+00:00",
    "color": "#182634",
    "widthMetres": 0.0015,
    "points": [{ "xMetres": 0.048, "yMetres": 0.072, "elapsedSeconds": 1.0 }]
  }]
}
```

| 項目 | 意味 |
|---|---|
| id | 空でないページ識別子。移行でも保持 |
| createdUtc / updatedUtc | 作成・最終更新時刻。UTC。更新は作成より前にならない |
| boardWidthMetres / boardHeightMetres | 現在の板の幅・高さ。正の有限値、単位m |
| isPinned | ★の有無。現在の新規ページと移行ページはfalse |
| title | 任意の文字列。省略・null・空文字はタイトルなし。新規ページとv1読込は空文字。表示名だけに使用し、ファイル名・ID・作成日時は変えない |
| color | 線の不透明なRGB色。`#RRGGBB`。小文字も読めるが大文字に統一 |
| widthMetres | 線の実寸の太さ。正の有限値。パレットは0.00075・0.0015・0.003m（0.75・1.5・3mm）。他の正の値も読込可 |
| points | 線の点列。空の線・空のページも表現可 |

ADR 0005の2026-10-20改訂に従い、`worldNames`は廃止した。新規保存やv1からの移行で出力しない。
古いv2にこの欄があっても、型や値を含めて無視する。読むだけでは元ファイルを書き換えず、保存時には従来どおり元JSONを.json.bakへ残す。
色は黒（#182634）・赤（#C53939）・青（#2464C4）・緑（#23834B）を選べる。isPinnedの操作UIは後続タスク。

### ページタイトル

`title` はv2の任意項目として追加し、`formatVersion` は2を維持する。線・座標・必須項目の解釈を変えず、古いv2のタイトル欠落を空文字として読めるため。文字列以外（nullを除く）は読込エラーにする。
タイトルの有無だけを理由に元JSONを書き換えず、通常保存時に `title` を出力する。上書き前のJSONは従来どおり `.json.bak` へ残す。
古いアプリでも未知の項目を無視して筆跡を読めるが、古いアプリで保存し直すとタイトルが失われる。

名前はPCから変更し、空文字で作成日時の表示に戻す。文字数の独自上限は設けず、UIで一行の幅に合わせて省略する。JSONの元文字列は保持し、表示時だけ改行・タブを空白にする。
複製はタイトルをそのまま引き継ぎ、新しい作成日時・IDで区別する。名前の変更履歴は筆跡の履歴とは別に、アプリ起動中だけページごとに保持する。JSONやPNGへ履歴は追加しない。
タイトルは操作UIの情報なので、保存PNGへは描かない。

### 座標と時刻

ページ左上が`(0,0)`、右がXの正方向、下がYの正方向。xMetres・yMetresの単位はメートル。
板に対する割合ではないため、板の寸法だけ変えても保存した座標と太さは変わらない。
負の座標や板の外の点も保持し、切り捨て・端への補正はしない。NaN・無限大は認めない。

elapsedSecondsは記録用時計の起点からの経過秒でv1と同じ。有限・非負で、一つの線の中では後戻りしない。
startedUtcは線の最初の点の絶対時刻。各点の時刻は次で復元できる。

`startedUtc + (その点のelapsedSeconds - 最初の点のelapsedSeconds)`

updatedUtcは保存時の更新時刻。UNDO後に残った点が古くなっても、その点の時刻へ戻さない。

### 消しゴムとUNDO

線ごと消しは触れた線をstrokesから取り除く。部分消しは円が移動した経路を線から取り除き、残った部分を別の線として同じ順序で保存する。
切断位置には点を補い、時刻も隣り合う点の間で補間する（距離に応じて間の値を求める）。色・太さは元の線と同じ。
単なる白塗りではないため、読み込んだ点列やPNGにも消えた部分が残らない。
最後の線を消した場合も空のページを保存する。UNDOは1本の筆記または1回のなぞりを戻し、復元した内容を保存する。
UNDO履歴、パレットの現在の選択、消しゴムの位置はJSONに記録しない。履歴はNEW PAGEやアプリ終了で破棄する。

## v1 の読込と移行

v1のu・vは板の左上を(0,0)、右下を(1,1)とする割合だった。読込時に、**ファイルに保存された当時の板の寸法**で換算する。

- xMetres = u × boardWidthMetres
- yMetres = v × boardHeightMetres
- 色は従来の#182634。
- 太さは3.2 × boardWidthMetres ÷ 1024メートル。旧PNGの3.2ピクセル幅を保つ。標準板の幅0.48mでは1.5mm。
- ID、作成・更新・線・点の時刻、板の寸法は保持。isPinned=falseを補う。worldNamesは付けない。

読込はメモリ内だけの変換で、元のJSONを書き換えない。起動時のPNG復旧でもv1のJSONはv1のまま。
そのページを保存するときに同じ名前へv2を書き、保存前に元のv1の**バイト列そのもの**を`元の名前.json.v1.bak`へ残す。

1. 上書き先の形式・内容・ページIDを検証。壊れたJSON、未知の版、異なるIDは上書きしない。
2. v1なら専用の一時ファイルに元データを書き、ディスクへフラッシュしてから.json.v1.bakへ確定する。
3. 専用バックアップが既にあればバイト一致を確認。不一致なら保存を止め、両方を残す。
4. バックアップを作れた後に通常保存を進める。以後v2を何度更新してもv1専用バックアップは書き換えない。

.json.bakは直前のJSONを残す通常のバックアップで、保存ごとに更新する。.json.v1.bakは移行前の原本として別に保管する。
専用バックアップを作れない場合はv1を置換しない。PNG出力に失敗しても、確定したJSONと移行前原本は残る。
利用者ファイルを一括で変換・改名・削除する処理はない。

## 保存とPNGの復旧

ゴミ箱の各隔離フォルダには `.trashed-at` を置き、`{"trashedUtc":"2026-10-23T00:00:00+00:00"}` のようにUTCの投入時刻を記録する。メモ本体の形式番号・項目は変えない。補助ファイルがない旧ゴミ箱は更新後の初起動時刻を書き、補助ファイルがなくてもメモを読める。不正なメタデータはエラーにして自動削除せず、本体が正常なら一覧と手動復元は利用できる。復元時には補助ファイルを外し、再投入時は新しい時刻を記録する。自動・手動の完全削除では関連ファイルとJSONの削除後に補助ファイルを消すため、失敗したページの起点は失わない。[判断理由](adr/0006-desktop-settings.md)。

保存時は同じフォルダーに一時 JSON を書き、OS のディスクへのフラッシュを完了してから正本へ置換する。既存 JSON は置換前に `.json.bak` として残す。JSON が成功した後で、PNG を同じ方法で置換する。PNG の失敗は JSON を取り消さないため、次回の保存または起動時の `RepairPreviews` で、存在しないか JSON より古い PNG を JSON から再生成できる。壊れた JSON は削除も上書きもせず、ファイル単位のエラーとして報告する。

この手順はプロセス強制終了時に「最後に置換まで完了した JSON」を残すことを目標にする。一時ファイルだけが残っても正本は読める。OS・ドライブ・電源断の種類によっては、電源断に対する絶対的な保証はできない。アプリは少なくともストローク終了、Undo、閉じる、新しいページ、終了時に同期保存し、書込み中断で失う範囲を直近の完了保存以降へ限定する。

PNGは約2133画素/mでページ全体を出力する。標準48×36cmは従来どおり1024×768、最大80×60cmは1707×1280画素（整数へ四捨五入）。背景色は従来と同じで、操作ボタン・カーソル・掴み候補表示を含めない。
保存済みの実寸座標を板の寸法に対して画像座標へ換算し、線ごとの色・太さで描く。
板の外の点はJSONに残り、PNGでは画像に収まる部分を描く。書いた範囲だけへの切り抜きは行わない。

### 板の大きさ

保存形式の版は2のまま、既存のboardWidthMetres・boardHeightMetresへページごとの寸法を保存する。新規ページは0.48×0.36m。
左上を基準に右・下へ広げ、線の実寸座標と太さ、色、時刻は保つ。入力中のUV（板に対する割合）は寸法に合わせて換算し直す。
上端のボタンと一覧のカードは標準板と同じ寸法・左上位置。見出しは左上から幅0.48m、上端から0.054〜0.1044mの帯で、右に広げた部分は本文として一覧画像を作る。
道具パレットは高さ0.0324m、ボタン部分は幅0.48mを保ち、現在の下端に配置する。

通常の操作範囲は0.48×0.36〜0.80×0.60m。縮小では現在の線とUNDOで復元できる線の右端・下端を調べ、線の半分の太さと2mmの余白、下端のパレットの高さも確保する。
UNDO履歴がなくなる再読込後は、現存する線だけが下限を決める。板の大きさ変更自体はUNDOの対象にしない。
既存ファイルの寸法は読込時に補正しない。操作上限より大きい既存ページでは、その寸法と線を保護するために必要な寸法を上限として縮小できる。
寸法の変更も保存対象となり、操作中は約1秒ごと、グリップ解放・中断時に確定保存する。PNGの再生成と保存失敗時の保持は既存の保存経路を使う。

必須項目の欠落、型の違い、nullの線・点、不正な数値・色・太さ・日時は読込エラー。
未知のformatVersionも拒否し、元ファイルを残す。他の正常なページのPNG復旧は続ける。
自動保存の契機（筆記中の約1秒ごと等）と、失敗時にページを残して再試行する扱いは従来どおり。
